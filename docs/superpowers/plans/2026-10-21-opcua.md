# OPC UA driver. Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax. Tick each step when it is done, in the same work block.

**Status:** Open. In progress (started 2026-10-21).

**Goal:** a read-only `opcua` input that connects with an explicitly trusted server certificate, reads points by
subscription (monitored items) or poll, maps status codes and timestamps to samples, recreates session and
subscriptions after a loss through its own loop, and gives the technician `opcua trust` and `browse`.

**Architecture:** the driver `internal/input/opcua` in four parts: configuration (connection, NodeId, point
checks), PKI (own certificate, trust store, thumbprints), conversion (variant to value, status to quality,
timestamp), and the input (session layer over the library, reconnect loop, subscription, poll groups, watchdog,
lifecycle, health). It reuses the Modbus plan's driver kit (`driverkit.Backoff`, `driverkit.Health`,
`input.HealthReporter`) and input contract (Start returns at once, background connect, `Close` never waits for a
dial, death after `death_tolerance`). Two new CLI commands, `opcua trust` and `browse`, use the same session layer.

**Tech Stack:** Go 1.27; new dependency `github.com/gopcua/opcua` v0.9.1 (MIT; a client-only build imports only the
standard library; its `server` package, used by tests only, brings `github.com/google/uuid` v1.6.0, BSD-3-Clause;
`testify`, MIT, and `golang.org/x/exp`, `golang.org/x/term`, BSD-3-Clause, appear only in `go.sum`) — approved by the user on 2026-10-21.

**Spec:** `../specs/2026-10-19-transforms-modbus-opcua-design.md` sections 2 (D3, D6), 6, 7; parent
`../../../../docs/superpowers/specs/2026-10-12-laraplate-edge-agent-design.md` 9.2, 10. Library facts below were
read from the v0.9.1 source and checked against its in-process server on 2026-10-21.

## Global Constraints

- AGPL-3.0 repo; permissive dependencies only; no CGO; module `github.com/getlaraplate/laraedge`; work on branch
  `develop`; commit only your own files in laraplate-edge; never push; no `Co-Authored-By` trailer; do not commit at
  the stack root.
- `gofmt -l .` empty, `go vet ./...`, `GOOS=windows go vet ./...`, `go test -race ./...`, `GOARCH=386 go test ./...`
  before every commit; table-driven tests; fakes over mocks; fake clock for scheduling, no sleeps (real sockets on
  127.0.0.1 are fine; synchronise on channels and emitted records).
- Read-only (parent 9.1): no Write, Call or node management request is ever sent.
- Input contract (core R47, spec D6, Modbus R2/R10): `Start` opens only local resources (the PKI) and returns; the
  server connection happens in the background; an unreachable or untrusted server is death after
  `death_tolerance` and birth on recovery, never a failing `Start`; `Close` never waits for a library dial.
- Values, endpoints, user names and passwords never appear in errors or logs at info and above. A server
  certificate thumbprint and an input id may.
- Spec section 6 values exactly: `endpoint` `opc.tcp://…`; `security_policy` `None`, `Basic256Sha256` (default),
  `Aes128_Sha256_RsaOaep`, `Aes256_Sha256_RsaPss`; `security_mode` `Sign` or `SignAndEncrypt` (default); `auth`
  anonymous or `{user, password: secret://…}`; `publishing_interval` default 1s; own certificate in
  `data_dir/opcua/pki/own/`, RSA 2048, application URI `urn:laraplate-edge:<agent_id>`, key mode `0600`; trusted
  certificates in `data_dir/opcua/pki/trusted/`; monitored item queue default 10, discard oldest; deadband absolute
  or `N%`; timestamp `SourceTimestamp`, else `ServerTimestamp`, else the agent clock; status classes Good,
  Uncertain, Bad to `good`, `uncertain`, `bad`; backoff 1 s to 1 min.
- Health kinds as in the Modbus plan: `timeout`, `connection`, `exception`, `decode`.

## Library facts that shape the design (gopcua v0.9.1)

- **No server certificate validation.** The client pins whatever certificate it is given; trust is ours:
  `opcua.GetEndpoints(ctx, url)` (over a None channel), `opcua.SelectEndpoint(eps, policy, mode)`,
  thumbprint `uapolicy.Thumbprint(ep.ServerCertificate)` (SHA-1 of the leaf DER), then
  `opcua.SecurityFromEndpoint(ep, tokenType)` pins it. A wrong pin fails `Connect` with `StatusBadTimeout`.
- **A `Client` is single use**; reconnecting is `Close` plus a new `NewClient`. `AutoReconnect(false)` is required for
  our loop; loss is signalled only through `StateChangedFunc` (`Disconnected`, then `Closed`).
- **Any ServiceFault tears the client down** (state goes `Closed`, publish loop stops) although the TCP session still
  works: never send a Read with more nodes than `MaxNodesPerRead` (i=11705) or an empty Read, never create more
  monitored items per call than `MaxMonitoredItemsPerCall` (i=11714). Per-item bad statuses are not faults.
- **No half-open detection**; keep-alive publishes are not delivered to us.
- **`nsu=` needs the server's NamespaceArray**: `ua.ParseExpandedNodeID(s, client.Namespaces())`, re-resolved after
  every connect.
- **Logs through the standard `log` default logger** (stderr); no injectable logger.
- **Can panic in its own goroutines** on malformed server data (no `recover` in the library).
- Test server (`github.com/gopcua/opcua/server`): supports Read, Browse, subscriptions, all four policies; ignores
  deadband filters; does not validate user names; accepts monitored items for unknown nodes (reports
  `BadNodeIdUnknown` later in a notification); cannot listen on port 0 usefully (pre-pick a free port, use
  `127.0.0.1`); `Close` does not drop live connections (use a small TCP proxy to simulate a loss); logs through the
  standard `log` package; values change with `ns.SetAttribute(id, ua.AttributeIDValue, server.DataValueFromValue(v))`.

## Decisions taken in this plan

- **O1. Trust.** On every connect with a policy other than `None`: discover endpoints, select the one matching
  `security_policy` and `security_mode`, compute the thumbprint (lowercase hex, 40 characters), accept only when
  `data_dir/opcua/pki/trusted/<thumbprint>.der` exists. Otherwise the attempt fails with kind `connection`, the
  certificate is written to `data_dir/opcua/pki/rejected/<thumbprint>.der`, and a WARN names the input, the
  thumbprint and the command `laraplate-edge opcua trust <input>` (once per thumbprint per input run, not at every
  retry). A newly trusted certificate is picked up at the next retry without a restart. Expiry is shown by
  `opcua trust`, not enforced (the operator's explicit trust decides).
- **O2. Own certificate.** Created by `Start` of the first `opcua` input (a local resource: failure fails `Start`), by
  `probe`, `browse` and `opcua trust` when missing: RSA 2048, SHA-256, validity 10 years, SubjectAltName URI
  `urn:laraplate-edge:<agent_id>` and DNS the host name, KeyUsage DigitalSignature, ContentCommitment,
  KeyEncipherment, DataEncipherment, CertSign; ExtKeyUsage ServerAuth and ClientAuth; files `own/cert.der` and
  `own/key.pem` (PKCS#8, mode 0600), written into a temporary directory renamed to `own/` so two processes never
  leave a mismatched pair (the loser of the rename reads the winner's pair).
- **O3. Fixed timing** (spec section 6 lists no timeout field): dial timeout 5 s, request timeout 5 s, session timeout
  60 s, subscription `MaxKeepAliveCount` 10, watchdog Read of `Server_ServerStatus_CurrentTime` (i=2258) every
  `min(5 s, death_tolerance / 3)`, at least 1 s. A failed watchdog read, a `Disconnected`/`Closed` state or a
  connect error closes the client and reconnects with `driverkit.Backoff`.
- **O4. Device liveness is the server's.** All devices of an input sit behind one server: every successful exchange
  (watchdog read, Read response, data notification) calls `Lifecycle.Read` for every device of the input. A node with
  a Bad status is a `bad` sample, not a dead device. So a subscription whose values never change keeps its devices
  alive.
- **O5. Limits.** After connect read `MaxNodesPerRead` and `MaxMonitoredItemsPerCall`; 0 means no limit; a Bad status
  or an unreadable value means 100. Reads and monitored item creation are chunked at that size; empty requests are
  never sent.
- **O6. Library logging.** `run`, `probe`, `browse` and `opcua trust` route the standard `log` output into the agent's
  slog logger at DEBUG with `source=gopcua` (`internal/logging.StdlogBridge`). Tests discard it.
- **O7. Panics.** Our calls into the library run under `recover` (a recovered panic is kind `connection` and a
  reconnect); a panic in a library goroutine cannot be recovered and stops the process (the service manager restarts
  it). Declared limit.
- **O8. Points.** `type` is required (bool, int16, uint16, int32, uint32, int64, uint64, float32, float64, string);
  `byte_order` is refused; `read: event` is refused. Conversion is lossless or `bad` (kind `decode`): integer variants
  to an integer type when in range, to a float type when exactly representable (at most 2^53 in magnitude); float32 to
  float64; float to an integer type never; Boolean only to `bool`; String only to `string`; arrays, DateTime and
  structures always `bad`. A value missing from a Good or Uncertain DataValue is `bad`. A `bad` sample carries the zero
  value of its kind (Modbus R9).
- **O9. Subscribe defaults.** One subscription per input at `publishing_interval`; `read: subscribe` uses sampling −1
  (the publishing interval), queue 10, discard oldest, no filter; the long form
  `read: {subscribe: {sampling, queue, deadband}}` sets them; a deadband sends a DataChangeFilter
  (trigger StatusValue; absolute, or percent for `N%`, which needs an EURange on the server). Monitored item results
  with a Bad status give one `bad` sample for that point and kind `exception`; the item is retried at the next
  reconnect only.
- **O10. Poll.** Points with `read: {poll: d}` are grouped by interval and read with the Read service
  (`TimestampsToReturnBoth`, chunks of O5), scheduled earliest-due first on the fake clock (Modbus R13 scheduler).
- **O11. Auth.** `auth` absent or `"anonymous"`: anonymous. `{user, password}`: the password is resolved through the
  secret resolver at every connect (a rotated `secret://file/` takes effect at the next connect); a resolution error
  is kind `connection`. `auth.user` with `security_policy: None` is refused offline (the password would travel in
  clear).
- **O12. `None`.** `security_mode` is ignored with `None` (mode None); no trust check; a WARN at every `Start` says
  the input's connection is unprotected (input id only).
- **O13. Factory options.** `opcua.Factory(opts opcua.Options) input.Factory` with
  `Options{DataDir, AgentID string; Resolver SecretResolver; Logger *slog.Logger}` with
  `SecretResolver interface{ Resolve(ctx context.Context, ref string) (string, error) }` (satisfied by
  `*secrets.Resolver`), built in `inputDrivers`
  from the bootstrap; factories still never touch the disk or the network (M1 of the Modbus plan).

## Review Focus

- The server comes back with a new certificate (reinstalled): the input refuses it, logs the new thumbprint once,
  dies after `death_tolerance`; after `opcua trust` the next retry connects without restarting the agent. Test in
  Task 5.
- A subscription whose values never change for longer than `death_tolerance`: the devices stay alive (O4). Test in
  Task 5.
- More points than the server's `MaxNodesPerRead` (the test server advertises 32): 70 poll points and 70 subscribe
  points are read and monitored without a ServiceFault and the client stays connected. Test in Task 5.
- An `nsu=` point when the server registers its namespaces in another order after a restart: the point resolves to
  the new index after the reconnect. Test in Task 5.
- One unknown node and one node of the wrong type among good ones: `bad` samples for those two only, the others keep
  their values, the connection is kept. Test in Task 5.
