# Modbus driver. Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax. Tick each step when it is done, in the same work block.

**Status:** Closed (2026-10-21). Shipped; see "Delivery status" below.

**Goal:** a read-only `modbus` input (TCP, RTU, RTU over TCP) that polls holding/input registers, coils and discrete inputs in contiguous blocks, decodes them by point type and byte order, maps Modbus errors to qualities and death/birth, and works against simulated servers in tests and CI.

**Architecture:** a reusable driver kit (`internal/input/driverkit`: reconnection backoff, request rate limiter, health counters) and the driver `internal/input/modbus` (connection and address parsing, block planner, decoder, poll loop). The driver builds on the core's input contract (Start returns at once, connection in the background, death after `death_tolerance` through `input.Lifecycle`), registers in the `run` driver registry, and becomes accepted by `CheckBuild`.

**Tech Stack:** Go 1.27; new dependency `github.com/simonvetter/modbus` v1.6.4 (MIT; brings `github.com/goburrow/serial`, MIT) — approved by the user on 2026-10-21.

**Spec:** `../specs/2026-10-19-transforms-modbus-opcua-design.md` sections 2 (D3, D6), 5, 7; parent `../../../../docs/superpowers/specs/2026-10-12-laraplate-edge-agent-design.md` 7.1, 9.1, 9.2.

## Global Constraints

- AGPL-3.0 repo; permissive dependencies only; no CGO; module `github.com/getlaraplate/laraedge`; work on branch `develop`.
- `gofmt -l .` empty, `go vet ./...`, `go test -race ./...`, `GOARCH=386 go test ./...`, `GOOS=windows go vet ./...` before every commit; table-driven tests; fakes over mocks; fake clock for scheduling, no sleeps or timing assertions.
- Drivers are read-only: no write function code is ever sent (parent 9.1). One request in flight per connection; `rate_limit` requests per second (default 20).
- Input contract (core R47, spec D6): `Start` opens only local resources (the serial port for `rtu`) and returns; the TCP connection happens in the background; an unreachable device is death after `death_tolerance` and birth on recovery, never a failing `Start`.
- Values and connection settings never appear in errors or logs at info and above; the library's own logger is silenced (it writes to stdout by default).
- Spec section 5 values exactly: transports `tcp`, `rtu`, `rtuovertcp`; port 502; `timeout` 1s; `unit_id` 1; `rate_limit` 20; address `<area>:<offset>[#<registers>][@<unit>]` with areas `hr`, `ir`, `co`, `di`, offsets 0–65535; register sizes `int16`/`uint16` 1, `int32`/`uint32`/`float32` 2, `int64`/`uint64`/`float64` 4, `string` n; `byte_order` `ABCD` (default), `CDAB`, `BADC`, `DCBA`; `bool` only on `co`/`di`; `poll` only; blocks of strictly contiguous addresses, at most 125 registers or 2000 bits; error table of spec section 5.
- Commit only your own files in laraplate-edge; never push; no `Co-Authored-By` trailer; do not commit at the stack root.

## Decisions taken in this plan

- **M1. Driver configuration is validated by the factory.** The schema keeps `connection` open (core R6); `modbus.Factory` parses the connection and every point address and type, with fixed messages naming the input and the point position. The supervisor already turns a factory error into `rejected`; `config validate` additionally builds each input through the driver registry (factories never connect, core R47) so driver errors show offline.
- **M2. Health reporting.** Inputs may implement `input.HealthReporter` (`Health() input.Health{Connected bool; ReadErrors map[string]uint64}`); the supervisor copies it into `InputStatus`; `/metrics` exposes `laraplate_edge_input_connected{input}` (gauge 0/1) and `laraplate_edge_input_read_errors_total{input,kind}` (counter, `kind` one of `timeout`, `connection`, `exception`, `decode`); `/status` gains `connected` and `read_errors`. `simulated` does not implement it (always connected, no series).
- **M3. Strings** decode as the register bytes in big-endian order per register, up to the first NUL; invalid UTF-8 is a `bad` sample (kind `decode`).
- **M4. Exceptions 5 and 6** retry at the next poll without a sample and without counting toward death; timeouts, connection errors and exceptions 10, 11 count toward death (no successful read); exceptions 1–4 give `bad` samples for the block and count as a successful exchange (the device answered).
- **M5. One client per input**, owned by its poll goroutine; units are switched with `SetUnitId` before each block; RTU over one serial port is one input.
- **M6. Test servers.** Modbus TCP: the library's server in process. RTU over TCP: a small RTU-framed server in the test package (CRC-16/Modbus). A real serial port is a declared limit (spec section 7).

## Review Focus

- The device stops answering mid-run (server stopped): no samples, `connected` 0, death after `death_tolerance`, birth and data again after restart of the server. Test in Task 5.
- A block straddling an unmapped address (exception 2): every point of that block is `bad`, other blocks unaffected. Test in Task 5.
- `float32` with byte order `CDAB` spanning two registers decodes the expected value; `int16` negative values sign-extend. Test in Task 4.
- Shutdown while a request is in flight (timeout 1 s): `Close` returns after at most the request timeout and nothing is emitted afterwards. Test in Task 5.
- A document where two points overlap the same registers with different types: both decode from the same block read. Test in Task 3.

## Delivery status (2026-10-21): shipped

All seven tasks are built on branch `develop`, each reviewed, then a whole-branch review, one fix wave and a
user-approved follow-up. The agent has a read-only `modbus` input for `tcp`, `rtu` and `rtuovertcp`: points are
parsed and checked by the factory (M1, so `config validate` builds every input offline and reports driver errors),
grouped into blocks of strictly contiguous addresses (at most 125 registers or 2000 bits), read under a request rate
limit with one request in flight, decoded by type and byte order, and mapped to qualities, death and birth through
the core's lifecycle helper. The driver kit (`internal/input/driverkit`) gives backoff, rate limiter and health;
`/metrics` exposes `laraplate_edge_input_connected{input}` and `laraplate_edge_input_read_errors_total{input,kind}`
and `/status` `connected` and `read_errors` for inputs that report health. Tests run against the library's Modbus TCP
server and an RTU-framed test server in process; the end-to-end test runs the built binary against a server started
by the test, through a stop and a restart. Commits from `393a3a7` to `f88e756`, and the closing commit. Dependency:
`github.com/simonvetter/modbus` v1.6.4 (MIT) with `github.com/goburrow/serial` v0.1.0 (MIT), approved 2026-10-21.
The divergences from the plan and the spec, each with its reason (the rulings are in "Controller rulings" below):

- **Byte orders defined (R7).** Two independent swaps: inside each register (`BADC`, `DCBA`) and low word first
  (`CDAB`, `DCBA`); 16-bit types only the byte swap; 64-bit low word first reverses all four registers; strings
  ignore `byte_order` (M3).
- **Error mapping (R1, R8, R15, R16).** Exceptions 1-4 and 8 give `bad` samples with the zero value of the kind
  (R9) and keep the device alive; 5, 6 and unknown exception codes are an answer without a sample; 10 and 11 give no
  sample and count toward death but keep the connection. The spec's "reconnection with backoff" after a timeout is
  replaced by R13 (next item).
- **Timeouts keep the connection (R13, R19).** The whole-branch review found that one silent unit or block starved
  every later block of the input (the scheduler restarted at block 0 after each reconnect), so a live unit behind a
  silent one was reported dead with the default timeout and poll. Fixed: blocks are served earliest-due first, their
  next due time is computed after the exchange, a timeout (and on `rtu`/`rtuovertcp` a bad CRC, protocol error or
  short frame, which the library flushes) keeps the connection; it reopens with the backoff on an I/O error, on a
  protocol error or short frame on `tcp` (the MBAP stream cannot resynchronise), or when no block of the input has
  answered for `death_tolerance`.
- **RTU late answers (R17).** RTU has no transaction id and the library does not flush the line after a timeout, so
  an answer arriving after `timeout` can be taken for a later request of the same unit, function and length. Not
  fixable in the driver; documented as a limit with the rule for choosing `timeout`.
- **Serial port (R2, R12).** `rtu` opens the port in `Start` (a failure rolls the document back with a fixed text);
  later failures reopen in the background. The port is not exclusive on Linux (goburrow takes no lock), so spec D6's
  "exclusive resource" holds on Windows only; the docs advise stopping the agent before probing an `rtu` input and
  never giving two inputs the same `device`.
- **`Close` never waits for a dial (R10).** The library's connect has a fixed 5 s timeout; the background open runs
  in a helper goroutine that closes a late-opened client itself.
- **Read-error counts per input start (R14).** They restart from 0 when the input is rebuilt (configuration change,
  rollback); `transform_errors` keeps its count across restarts.
- **Connection parsing (R5, R6).** Unknown `connection` fields are refused; `baud` is required for `rtu`; unit 0 is
  accepted.
- **Plan closed by the controller (R11)**; Task 7 Step 3 was not dispatched.
- **Also fixed:** a flaky test of the agent core, `TestNextNeverSpinsOnACountWithoutRecords` (internal/output), which
  hung master's CI once: `Next` could return before the test's second wake-up.
- **Not done, deferred:** the review's minor findings left open (backoff code shared with `internal/output`, the type
  table listed twice in `config.go`, a distinct text for a missing or forbidden serial device, the Linux-only
  real-time `Close` test, a real serial port in CI, which is a declared limit of spec section 7).

**Documented in:** `docs/CONFIGURATION.md`, `docs/USAGE.md` (and `README.md`, `examples/modbus/`).

## Controller rulings (subagent-driven execution, 2026-10-21)

Every ruling the controller took while executing this plan, copied verbatim from its execution ledger,
with what each costs if wrong. The Delivery status above cites them by number.

- R0 Ruling: plan text corrected before execution (module github.com/getlaraplate/laraedge, no Co-Authored-By trailer per user's global instructions, dependency approved 2026-10-21) — user's CLAUDE.md overrides the plan — cost if wrong: commits lack a trailer, cosmetic.
- R1 Ruling: exceptions 5/6 are a device answer: no sample, but Lifecycle.Read(device) is called (the device is reachable), so a busy device never dies — M4 contrasts them with "no successful read" cases and Lifecycle is time since last read, so "not counting" can only mean resetting it — cost if wrong: a permanently busy device stays alive with stale values; one-line change.
- R2 Ruling: for transport rtu, Start opens the serial port synchronously through the client (open failure = Start error, local resource, core R47); later serial failures go through the same background reconnect/backoff path as TCP. tcp and rtuovertcp connect only in the background goroutine — spec D6 — cost if wrong: small restructuring of Start in Task 6.
- R3 Ruling: scheduling, backoff and rate limiting use the fake clock; network I/O in tests is real (library server / raw listeners on 127.0.0.1:0) with short configured timeouts; tests synchronise on channels/emitted records, never sleep; bounds on Close are generous (assert it returns, under a deadline of several seconds) — global constraint forbids sleeps and timing assertions, but real sockets cannot run on a fake clock — cost if wrong: flaky tests caught by -race -count=30.
- R4 Ruling: the binary and metric names keep laraplate-edge / laraplate_edge_ (the rename commit kept protocol identifiers and cmd/laraplate-edge) — cost if wrong: rename later, mechanical.
- R5 Ruling: modbus connection unknown fields are refused with a fixed message naming the field (never the value); durations parse as config does — plan silent; strictness catches typos like 'unitid' — cost if wrong: a document with an extra field is rejected, easy to relax.
- R6 Ruling: unit 0 stays accepted (unit_id and @0) — Modbus TCP devices commonly answer on unit 0 and the spec does not forbid it; on RTU it is broadcast and simply times out — cost if wrong: a misconfigured RTU point dies instead of being refused offline.
- R7 Ruling: byte_order semantics: two independent swaps — byte swap inside each register (BADC, DCBA) and word order low-word-first (CDAB, DCBA). For 16-bit types only the byte swap applies; for 64-bit types low-word-first reverses all four registers (as simonvetter/modbus LowWordFirst does). Strings ignore byte_order (M3, big-endian per register) — spec names the four orders without defining 1- and 4-register cases; this is the common library convention — cost if wrong: a device with pairwise 64-bit word swap needs a new order value.
- R8 Ruling: Modbus error mapping — 1-4 bad samples + Read + kind exception; 10/11 no sample, no Read, kind exception, connection kept; timeout/connection error: no sample, close + reconnect with backoff, kinds timeout/connection; backoff Reset after a successful exchange — spec table plus M4; reconnect after timeout because a TCP stream may be desynchronised — cost if wrong: extra reconnects on a slow device.
- R9 Ruling: driver bad samples carry the zero value of the point kind — model requires a valid Value; matches the transform convention documented in CONFIGURATION.md — cost if wrong: backend shows 0 with quality bad, which it already handles.
- R10 Ruling: Close waiting up to 5 s during a library dial is fixed in Task 6, which restructures Open anyway (rtu synchronous open, R2): background Open runs in a helper goroutine and Close/cancel does not wait for it (the helper closes the client when Open returns) — supervisor stopInput calls Close synchronously, so a reload would stall 5 s per black-holed input — cost if wrong: small extra scope in Task 6.
- R11 Ruling: Task 7 implementer does e2e, example and docs; the controller closes the plan (delivery status, rulings appendix, indexes) after the final review — the closing text must reflect the final review and the rulings, which only the controller holds — cost if wrong: none.
- R12 Ruling: finding (2) contradicts the controller's own task-7-context text; the reviewer is right (goburrow serial_posix.go opens without exclusive lock) — docs state it as advice (stop the agent before probing an rtu input; two readers corrupt each other's frames; Windows refuses a second open) — cost if wrong: none, wording.
- R13 Ruling: amends R8 — a timeout (and bad CRC/protocol/short frame) keeps the connection, the library resynchronises (TCP ignores unknown transaction ids; RTU flushes after bad CRC/protocol/short frame); reconnect only on I/O errors or when no block of the input has answered for death_tolerance; scheduler serves earliest-due first with next computed from clk.Now() after the exchange — the final review reproduced starvation of a live unit behind a silent one with default timeout and poll — cost if wrong: a desynchronised stream the library does not catch would stay open until death_tolerance passes.

- R15 Ruling: unknown exception codes are a device answer like 5/6 (no sample, Lifecycle.Read, kind exception, connection kept) — the device sent a well-formed exception frame — cost if wrong: a device answering only unknown exceptions stays alive with stale values.
- R16 Ruling: exceptions 10/11 count as an answer for the R13 "nothing answered for death_tolerance" reconnect rule — the gateway answered, so the connection is healthy and reopening it cannot help — cost if wrong: one line in apply.
- R17 Ruling: the RTU late-answer risk is accepted (no transaction id in RTU; a late reply matching unit, function and length is rare, and reconnecting on every timeout starved live units) — cost if wrong: a rare misattributed value after a timeout on RTU; mention in the docs' limits if the re-review agrees.
- R18 Ruling: residuals not dispatched (one fix wave only); surfaced to the user with a recommended small follow-up (docs limit + tcp protocol error/short frame as linkBroken) before merge — cost if wrong: merging misleading timeout advice.
- R19 Ruling: amends R13 for tcp only — ErrProtocolError and ErrShortFrame reconnect (MBAP stream cannot resync); tcp timeouts stay connection-kept; rtu/rtuovertcp unchanged (library flushes) — cost if wrong: a reconnect on a rare malformed tcp frame.
