# Plans

Agent-only plans of `laraplate-edge`. The design lives at the stack root:
`docs/superpowers/specs/2026-10-12-laraplate-edge-agent-design.md`.

- `2026-10-16-agent-core.md` (**closed**, 2026-10-19): the agent core in 11 tasks — module and CLI, model and envelope, bootstrap and secrets, disk buffer, sealed batches, HTTP output, configuration document, pipeline and supervisor with the `file` and `laraplate` providers, the `simulated` input, status endpoint and watchdog, end to end and docs. Transforms, CEL, real drivers, MQTT output, plugins and packaging are later plans.
- `2026-10-19-transforms.md` (**closed**, 2026-10-20): the level-1 transform catalogue, a processor per input with the persisted `edge_counter` state, the chain type check, the birth data type from the chain, the transform error metric, `probe` and `config test`; plus a Task 0 that fixed the three CI failures of master. First of the three plans of `../specs/2026-10-19-transforms-modbus-opcua-design.md`; `modbus` and `opcua` follow.
- `2026-10-20-modbus.md` (**closed**, 2026-10-21): the `modbus` input (TCP, RTU, RTU over TCP), the driver kit (backoff, rate limiter, health metrics) and `config validate` building inputs offline; plus the fix of a flaky agent-core test. Second of the three plans of `../specs/2026-10-19-transforms-modbus-opcua-design.md`.
- `2026-10-21-opcua.md` (**closed**, 2026-10-22): the `opcua` input (explicit certificate trust, subscriptions and poll, own reconnect loop, watchdog), the commands `opcua trust` and `browse`. Third of the three plans of `../specs/2026-10-19-transforms-modbus-opcua-design.md`.
- `2026-10-26-plugin-host-inputs.md` (open): the plugin host (offline validation against manifests, supervised processes with hashes, health, restart, memory limit and logs) and plugin inputs; `probe`/`browse` on plugin inputs; the built-in `simulated` driver through the SDK conformance suite. Plan 2 of the stack spec `2026-10-22-laraedge-plugins-design.md`; plugin processors and outputs are plan 3.
