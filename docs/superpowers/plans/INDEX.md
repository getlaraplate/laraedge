# Plans

Agent-only plans of `laraplate-edge`. The design lives at the stack root:
`docs/superpowers/specs/2026-10-12-laraplate-edge-agent-design.md`.

- `2026-10-16-agent-core.md` (**closed**, 2026-10-19): the agent core in 11 tasks — module and CLI, model and envelope, bootstrap and secrets, disk buffer, sealed batches, HTTP output, configuration document, pipeline and supervisor with the `file` and `laraplate` providers, the `simulated` input, status endpoint and watchdog, end to end and docs. Transforms, CEL, real drivers, MQTT output, plugins and packaging are later plans.
- `2026-10-19-transforms.md` (**closed**, 2026-10-20): the level-1 transform catalogue, a processor per input with the persisted `edge_counter` state, the chain type check, the birth data type from the chain, the transform error metric, `probe` and `config test`; plus a Task 0 that fixed the three CI failures of master. First of the three plans of `../specs/2026-10-19-transforms-modbus-opcua-design.md`; `modbus` and `opcua` follow.
- `2026-10-20-modbus.md` (**closed**, 2026-10-21): the `modbus` input (TCP, RTU, RTU over TCP), the driver kit (backoff, rate limiter, health metrics) and `config validate` building inputs offline; plus the fix of a flaky agent-core test. Second of the three plans of `../specs/2026-10-19-transforms-modbus-opcua-design.md`.
- `2026-10-21-opcua.md` (**closed**, 2026-10-22): the `opcua` input (explicit certificate trust, subscriptions and poll, own reconnect loop, watchdog), the commands `opcua trust` and `browse`. Third of the three plans of `../specs/2026-10-19-transforms-modbus-opcua-design.md`.
- `2026-10-26-plugin-host-inputs.md` (**closed**, 2026-10-29): the plugin host (offline validation against manifests, supervised processes with hashes, health, restart, memory limit and logs) and plugin inputs; `probe`/`browse` on plugin inputs; the built-in `simulated` driver through the SDK conformance suite. Plan 2 of the stack spec `2026-10-22-laraedge-plugins-design.md`; plugin processors and outputs are plan 3.
- `2026-10-29-plugin-processors-outputs.md` (**closed**, 2026-10-30): plugin processors (`processors[]`, observe and derive, derived devices as a virtual input) and plugin outputs (`type: plugin:<id>`, one output loop behind a `Sender` shared with `laraplate-http`); SDK v0.1.1. Plan 3 of the stack spec `2026-10-22-laraedge-plugins-design.md`.
- `2026-11-02-processor-state-output-wake-socket-dir.md` (**closed**, 2026-11-02): a processor stream opens with the current state of its observed devices, a plugin output in backoff is woken when its plugin is back, `run_dir` and a private temp fallback for plugin sockets; closes the limits left open by plan 3 and resolves its deferred minor findings.
- `2026-11-04-deferred-minors-cleanup.md` (**closed**, 2026-11-04): the minor findings the closed agent plans deferred (agent core, transforms, modbus, opcua, plugin host) and the items plan 2026-11-02 carried: `clock.Fake.BlockUntil` and no `runtime.Gosched` waits in the tests, command line, model, buffer, output, status, configuration, transform, supervisor and driver minors, three file splits.
- `2026-11-06-mqtt-json.md` (**open**): the `mqtt` input with JSON and plain payloads (paho client, `topic|path` addresses, availability topics, persistent session and subscription set, `probe` and `browse`). Plan 1 of the two of `../specs/2026-11-06-mqtt-driver-design.md`; Sparkplug B is plan 2.
