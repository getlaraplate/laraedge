# File driver, Q-DAS reports. Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax. Tick each step when it is done, in the same work block.

**Goal:** `format: qdas` on the `file` input: Q-DAS ASCII reports, as one `.dfq` or as a `.dfd` + `.dfx` pair, read once into typed samples with the part's context, and shown by `probe` and `browse`.

**Architecture:** a pure Q-DAS reader turns the text into a description (characteristics by index) and value records (one per part, from value lines or coded `K0001/i` lines, with their additional data); a pure mapper turns records into samples and read error kinds, as `parseCSV` does. The scanner learns *reports*: a report is one file, or a `.dfx` with its `.dfd`, hashed, committed and moved together. `probe` and `browse` dispatch on the format.

**Tech Stack:** Go 1.27, standard library only; no new dependency.

**Spec:** `../specs/2026-11-18-file-driver-design.md` sections 4, 5, 7, 8 and 10 (plan 2); plan 1 `2026-11-18-file-csv.md` for every rule this plan does not change.

## Sources of the format

Spec section 7 asks for the field numbers and separators to come from the AQDEF document. The Q-DAS ASCII transfer format manual (V12) and the AQDEF excerpt are published by Q-DAS but refused automated download (HTTP 403) when this plan was written, so the details below come from these three public sources, which agree with each other. The spec is amended at the plan's close to name them:

- Hexagon, *PC-DMIS Q-DAS Converter, User Manual* (version 5, 2025-01-23), `files.ms.hexagonmi.com`: the K-field list (K0001 value, K0002 attribute, K0004 time, K0005 events, K0006 batch, K0007 cavity, K0008 inspector, K0010 machine, K0011 process parameter, K0012 gage, K0014 part ID, K0053 order, K0100 number of characteristics, K1001 part number, K2001 characteristic number, K2002 description, K2004 characteristic type, K2101 nominal, K2110 and K2111 lower and upper limit, K2142 unit); "Valid (0); not marked: Invalid (255 or 256)"; `.dfq` and `.dfd` + `.dfx`.
- `aqdef-reader` (Apache-2.0, `github.com/SW4T400/aqdef-reader`, written to the V12 manual), read for facts only, no code taken: characteristics of a value line separated by `0x0F`, fields of one characteristic by `0x14`, in the order value, attribute, date and time, events, batch, cavity, inspector, machine, process parameter, gage; attributes 255 and 256 excluded; a coded line is the key, an optional `/index`, one space, the value; a key without index is index 1.
- Zeiss quality forum, a Calypso `.dfq`: `K0004/1 03.05.2021/14:12:50`, the date and time layout `DD.MM.YYYY/hh:mm:ss`.

## Decisions taken in this plan

- **Q1. Settings.** No `qdas` block: `connection.csv` and `connection.timestamp` are refused with `format: qdas` (the timestamp is `K0004`, spec section 7). `context` values are K-field keys `K0005` to `K0099` (`K` and four digits, upper case); with `csv` they stay column names. `encoding` applies as for CSV; the documentation advises `windows-1252` for exporters on Windows.
- **Q2. Lines.** Lines end with LF or CRLF; blank lines are skipped. A line starting with `K` is coded: `K` and four digits, an optional `/` and a decimal index, then one space or the end of the line; the rest, trimmed, is the value. A line starting with `K` that does not have this shape makes the file `malformed_file`. A key without index is index 1. Any other non-blank line is a value line. Well-formed keys the driver does not use are ignored.
- **Q3. One part type per file.** `K1xxx` with an index above 1 makes the file `malformed_file`: a CMM report carries one part type; several would need a characteristic-to-part mapping the sources do not settle.
- **Q4. Characteristics.** Their number is `K0100` when present, else the highest index of the `K2xxx` lines. A `K2xxx` or `K0xxx` index above `K0100` makes the file `malformed_file`. A value line or a coded value before any characteristic is defined makes the file `malformed_file`.
- **Q5. Records.** A value line is one record: it must hold exactly as many `0x0F`-separated blocks as there are characteristics, else its samples are `bad` with one `malformed_row`. Fields beyond the tenth of a block are ignored; missing trailing fields are empty. Coded values: `K0001/i` starts a new record when the current one already has a value for `i`, else adds to it. A coded `K0002` to `K0099` with index `i` after a record sets that field of characteristic `i` in the last record; with index `0` it sets it for the whole record; before any record it is ignored.
- **Q6. Per sample.** Value: the block's `K0001`, converted with `driverkit.ConvertText` (decimal point `.` only; a `,` is a `conversion` error). Empty: no sample. `K0002` `255` or `256`: no sample, no count. Timestamp: the characteristic's own `K0004`, else the record's `/0`, else the record's lowest-index `K0004`; a record without any `K0004` takes the modification time when it is the file's only record, otherwise the file is `malformed_file` (spec section 7); an unreadable `K0004` makes that record's samples `bad` with one `bad_timestamp`. Context: for each mapped key the record's `/0` value, else the value of the lowest characteristic index that has one; an absent field gives no key and no count.
- **Q7. Attributive characteristics** (`K2004` `1`) have a different value block that the sources do not settle; a point addressing one gets no sample and one `missing_field` per file. `browse` marks them. Recorded as a known limit.
- **Q8. Reports.** Under `qdas` only `.dfq`, `.dfd` and `.dfx` names are considered (after `pattern`, which must match both names of a pair). A `.dfq` is a report alone. A `.dfx` is a report with the `.dfd` of the same base name when both are stable; read as the `.dfd` text, a line end, then the `.dfx` text. A `.dfd` is never a report alone. Its ledger key is the SHA-256 of the 8-byte big-endian length of the `.dfd`, the `.dfd` bytes, then the `.dfx` bytes, with the `.dfx`'s modification time; its ledger name is the `.dfx` name. `max_file_size` applies to each file. Both files are committed and moved together, under one free suffix (`a-1.dfd`, `a-1.dfx`); a move that fails for either counts `move_failed` once per report and is retried for the file still there. `max_files_per_scan` counts reports.
- **Q9. A `.dfx` without its `.dfd`** waits; `browse` shows it with the new state `incomplete`. A `.dfd` shared by many `.dfx` files of other names (the counter layout of Q-DAS monitoring folders) is not supported: recorded as a known limit.
- **Q10. `K0004` without seconds** (`DD.MM.YYYY/hh:mm`) is accepted too: the sources show seconds, and a missing seconds field is harmless to read.
