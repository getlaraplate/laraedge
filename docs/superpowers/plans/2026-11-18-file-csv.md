# File driver, sample context and CSV. Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax. Tick each step when it is done, in the same work block.

**Goal:** an optional context per sample (`serial`, `order_ref`, `operation_ref`, `lot`) carried from the driver to the backend, and a read-only `file` input that polls a directory, reads each finished CSV report once (ledger by hash and modification time, deferred commit, `done/` and `error/`), turns it into typed samples with the part's context, and offers `probe` and `browse`.

**Architecture:** the core gains `model.Context` on `model.Sample`, written by the envelope and kept by transforms and the buffer. Text conversion, size parsing and `PointRef` move from `mqtt` to shared places so both drivers use them. The driver `internal/input/file` has a pure configuration parser, a pure stability watcher, a ledger file under `data_dir/file/seen/`, a pure CSV parser (bytes to samples), and the input itself: one goroutine scanning every `interval` on the injected clock, emitting, committing one scan later, moving files. It registers in the `run` registry, becomes accepted by `CheckBuild`, and plugs into `probe` and `browse`.

**Tech Stack:** Go 1.27; standard library `encoding/csv`, `crypto/sha256`, `time/tzdata`; `golang.org/x/text/encoding/charmap` (BSD-3-Clause), already in the module graph at v0.43.0 as an indirect dependency, made direct (spec F10, approved with the spec on 2026-11-18). No other new dependency.

**Spec:** `../specs/2026-11-18-file-driver-design.md` sections 1 to 6, 8, 9 and 10 (plan 1); parent `../../../../docs/superpowers/specs/2026-10-12-laraplate-edge-agent-design.md` 4, 9.1, 9.2; `../specs/2026-10-19-transforms-modbus-opcua-design.md` D6 and section 7 (driver kit, `probe`); `../specs/2026-11-06-mqtt-driver-design.md` (conventions this driver follows).

## Global Constraints

- AGPL-3.0 repo; permissive dependencies only; no CGO; module `github.com/getlaraplate/laraedge`; work on the branch `feat/file-csv` from `master`, merged through a pull request into `master` by the user.
- `gofmt -l .` empty, `go vet ./...`, `go test -race ./...`, `GOARCH=386 go test ./...`, `GOOS=windows go vet ./...` before every commit; table-driven tests; fakes over mocks; fake clock for scheduling, no sleeps or timing assertions (`clock.Fake.BlockUntil` to wait for timers); temporary directories from `t.TempDir()`.
- The driver never writes anything but `done/`, `error/` under the watched directory and its own ledger under `data_dir`; `probe` and `browse` write nothing at all.
- Input contract (core R47, spec D6): `Start` does no I/O on the watched directory and returns; scanning runs in the background; a missing or unreadable directory is death after `death_tolerance`, never a failing `Start`.
- Values read from files, file contents and context values never appear in errors or in logs at info and above; file names may.
- Spec values exactly: `format` `csv` (`qdas` refused in this build); `pattern` default `*`, Go `path.Match`, case-insensitive; always skipped: a leading `.`, names ending in `.tmp`, `.part`, `~`; `interval` default `2s`, at least `500ms`; `stable_for` default `5s`, at least `interval`; `max_file_size` default `16MiB`; `max_files_per_scan` default `100`; `after_read` `move` (default) or `keep`; `seen_retention` default `30d`; `encoding` `utf-8` (default), `windows-1252`, `iso-8859-1`, a UTF-8 byte order mark skipped; `timezone` IANA, default the agent's local zone; context keys `serial`, `order_ref`, `operation_ref`, `lot` only; `csv.delimiter` default `,`; `csv.decimal` `.` (default) or `,`, `,` refused with delimiter `,`; `csv.header_row` default `1`; `csv.layout` `wide` (default) or `long`, `key_column` and `value_column` required for `long`; timestamp formats `rfc3339`, `unix_s`, `unix_ms` or a layout of the tokens `YYYY`, `MM`, `DD`, `hh`, `mm`, `ss` with literal separators; ledger `data_dir/file/seen/{input_id}.json`; read error kinds `listing`, `file_too_large`, `malformed_file`, `malformed_row`, `missing_field`, `conversion`, `bad_timestamp`, `move_failed`; read mode `event` only, `type` required.
- Commit only your own files in laraedge; never push; no `Co-Authored-By` trailer; do not commit at the stack root.

## Decisions taken in this plan

- **P1. Validation by the factory**, as modbus M1 and mqtt Q1: the schema keeps `connection` open; `config validate` shows the factory's fixed messages, naming the field path, never a value.
- **P2. `model.Context`** is a struct `{Serial, OrderRef, OperationRef, Lot string}` held by pointer in `model.Sample.Context` with the tag `json:",omitempty"`: nil means no context, the buffer record of a sample without context is byte-for-byte what it is today, and old records decode unchanged (spec section 9). A driver sets nil rather than an all-empty context; the envelope writes no `context` for an all-empty one either.
- **P3. Shared helpers.** `mqtt`'s plain-text conversion (`convertText` and its helpers), its zero value of a type, its size parser and `PointRef` move to `internal/input/driverkit` and `internal/input`, unchanged in behaviour, so `file` reuses them (DRY) and `cmd` probes both drivers through one interface.
- **P4. `seen_retention`** is a Go duration or `<n>d` (days), at least `1h`.
- **P5. Time zones.** The `file` package imports `time/tzdata`, so IANA names resolve on Windows and on minimal images without a zoneinfo database (about 450 KB on the binary).
- **P6. Corrupt ledger.** A ledger that does not parse is renamed `{input_id}.json.corrupt-<unix seconds>`, logged at warn, and the input starts with an empty one; reports still present are read again, and the backend drops their repeated samples (spec section 5).
- **P7. Commit delay** is `max(interval, 1s)` after the emit (spec section 5).
- **P8. Refused files** (`malformed_file`, `file_too_large`) are committed like read ones, so with `keep` they are not retried until they change; with `move` they go to `error/`.
- **P9. `laraplate_edge_file_files_total` is not built.** Spec section 8 names it, but the status endpoint takes input metrics only from `input.Health` (connected and read errors); a per-driver counter needs that interface widened for every driver. Each file read, duplicate or refused is logged at info with its outcome instead, and refused files are counted by their read error kind. The spec is amended at the plan's close.
- **P10. `probe` names the file it read** (a `source:` line) and does not list the pending files: listing them is `browse`'s job, where the file states are shown. The spec's `probe` paragraph is amended at the plan's close.

## Review Focus

- A CSV saved by Excel on a European Windows PC: `;` delimiter, decimal comma inside quoted fields (`"12,5"`), CRLF line ends, `windows-1252` header names with accents, a trailing empty line. Every value converts; nothing is `malformed_row`. Test in Task 5.
- An exporter that writes `report.tmp` and renames it to `report.csv`: the `.tmp` is never read, the `.csv` is read once after `stable_for`, and its modification time, preserved by the rename, is its timestamp. Test in Task 6.
- The agent restarts between the emit and the commit: the same file is read again with identical timestamps and context (so the backend drops the repeats), and is committed afterwards. Test in Task 6.
- A network share that disappears and comes back: no sample, no file moved and no ledger change while it is gone; death after `death_tolerance`; birth at the first successful listing; files present are read normally afterwards. Test in Task 6.
- A file the driver may read but not move (read-only share with `move`): `move_failed` counted once, the file is never read twice, the input keeps running. Test in Task 6.

Behaviour, every `interval` on the clock:
1. Commit the pending files emitted at least `max(interval, 1s)` ago (P7): `ledger.Add`, `Save`, then with `move` rename into `done/` or, for refused files, `error/` (`os.MkdirAll` on first use; a taken name gets `-1`, `-2`, … before the extension; rename errors count `move_failed` once per file name and are logged at warn once); with `keep` remember name, size and modification time.
2. List the directory. Failure: count `listing`, `SetConnected(false)`, nothing else this scan (the lifecycle kills the devices after the tolerance). Success: `SetConnected(true)`, `Lifecycle.Read` for every device, `ledger.Prune` with the names listed.
3. `watcher.Ready`; drop pending files and, with `keep`, files whose name, size and modification time are remembered; take at most `max_files_per_scan`.
4. For each: larger than `max_file_size` → refused (`file_too_large`); a read error → skip, retried next scan; hash and modification time in the ledger → duplicate (with `move` moved to `done/` at once, with `keep` remembered), no samples; else `parseCSV`, emit each sample as `model.SampleRecord`, count `kinds`, log at info `file read` (input, file, samples, outcome), and hold it pending.

`Close` stops the loop and waits; pending files are not committed.
