# Serial driver Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax. Tick each step when it is done, in the same work block.

**Goal:** the `serial` input driver: one port per input, frames cut by terminator, length or gap, routed to points by regular expression, a scanned barcode setting the sample context of the measurements that follow, request commands for instruments that answer only when asked, with `probe` and `browse`.

**Architecture:** a new package `internal/input/serial` in the shape of `internal/input/file`: a `Port` interface with a production opener on `go.bug.st/serial` and a fake in the tests; three pure parts driven by explicit times (the framer, the router with the context, the request scheduler); an `Input` whose one goroutine opens the port with backoff, reads with a 100 ms timeout, feeds the pure parts and emits. `cmd/laraplate-edge` registers the factory and dispatches `probe` and `browse`.

**Tech Stack:** Go 1.27; `go.bug.st/serial` v1.8.0 (BSD-3-Clause, requires only `golang.org/x/sys`, already direct); `golang.org/x/text/encoding/charmap`, already direct.

**Spec:** `../specs/2026-11-19-serial-driver-design.md`; parent `../../../../docs/superpowers/specs/2026-10-12-laraplate-edge-agent-design.md` sections 9.1 and 9.2.

## Global Constraints

- AGPL-3.0 repo; module `github.com/getlaraplate/laraedge`; no CGO (`CGO_ENABLED=0` in CI); work on the branch `feat/serial` from `master` (worktree `.worktrees/serial`), merged through a pull request into `master` by the user.
- One new dependency only: `go.bug.st/serial` v1.8.0, approved by the user with the spec (approach A). Its `enumerator` package uses CGO only in `usb_darwin.go` (macOS, no production support); the Linux and Windows files are pure Go. Verified on 2026-11-19 from the module source.
- `gofmt -l .` empty, `go vet ./...`, `go test -race ./...`, `GOARCH=386 go test ./...`, `GOOS=windows go vet ./...`, `GOOS=linux GOARCH=arm GOARM=7 go build ./...` before every commit; table-driven tests; fakes over mocks; fake clock (`clock.Fake`, `BlockUntil`), no sleeps or timing assertions; pseudo-terminal tests carry `//go:build linux`.
- Error texts name the input and the field path (`connection.framing.gap`, `devices.<d>.points.<p>`), never a value, a frame or a context value. Frames and context values never appear in logs at `info` and above, except the context change line of spec section 9 (key and value at `info`, as the spec says) and unmatched frames at `debug` (quoted, truncated to 80 bytes, rate-limited).
- Spec values exactly: `data_bits` 5 to 8, default 8; `parity` `none`, `even`, `odd`, default `none`; `stop_bits` 1 or 2, default 1; `framing` default `{terminator: "\r"}`; `terminator` 1 to 4 bytes; `length` 1 to `max_frame`; `gap` at least `20ms`; `start` one character; `max_frame` default 1024; stale bytes dropped `2s` after the last byte (not with `gap`); `encoding` `utf-8`, `windows-1252`, `iso-8859-1`, default `utf-8`; context keys `serial`, `order_ref`, `operation_ref`, `lot`; rule `group` default 1, 0 for the whole match; `every` at least `100ms`; `request_timeout` default `1s`; `command` 1 to 64 bytes; read timeout 100 ms; read error kinds `open`, `port_lost`, `frame_too_long`, `incomplete_frame`, `decode`, `unmatched`, `conversion`, `no_response`.
- Commit only your own files in laraedge; never push; no `Co-Authored-By` trailer; do not commit at the stack root (the parent spec amendment of Task 8 is left in the stack working tree for the user, and named in the PR).

## Decisions taken in this plan

- **R1. Library.** `go.bug.st/serial` v1.8.0 no longer brings `creack/goselect` (the spec's S12 named it from an older release); on Linux and the BSDs it takes exclusive access with `TIOCEXCL` on open, so a second non-root open of the same port fails with "busy" (spec section 8, first branch). Recorded in the spec at the close.
- **R2. `browse` needs an input**, like every `browse` of the agent: `browse <input>` lists the ports and marks the input's `device`. A technician without a document writes a one-input document with any `device`; the documentation shows it. The spec's `browse [<input>]` is amended at the close.
- **R3. `probe` has no `--wait`.** It uses the agent's existing `probeTimeout` (30 s), as `mqtt` does, and returns as soon as every point has a sample. The spec's `--wait 10s` is amended at the close.
- **R4. Probe notes.** `probe` prints the context it saw and up to ten unmatched frames through a new optional interface in `cmd/laraplate-edge/probe.go`, `probeNoter` (`ProbeNotes() []string`), after the point lines; probe is an operator tool and prints frames on purpose, as it prints samples.
- **R5. The opener is a dependency.** `Input` takes its opener and its port lister through a `deps` struct (nil means production), as `file` takes its file system operations, so every lifecycle test runs on a fake port and the fake clock.
- **R6. Priority.** Samples take the point's priority exactly as the `file` driver sets it; read `internal/input/file/report.go` and do the same.

## Review Focus

- A gauge that sends `"\r\n"` while the input says `terminator: "\r"`: every frame read once, no empty frame counted, no `"\n"` in front of the next value. Test in Task 3.
- An operator scans part A, measures, scans part B, measures; a measurement whose frame was read before B's scan but routed after it still carries A. Test in Task 4.
- A USB adapter unplugged mid-frame and plugged back in: the half frame is dropped (not joined to the first frame after reopening), the context survives, the devices die only after `death_tolerance`. Test in Task 6.
- Two requests due at the same moment on a multiplexer whose channel 1 never answers: channel 2 is still asked every cycle, one `no_response` per unanswered command, never two commands on the wire at once. Test in Task 5.
- A frame of `windows-1252` text with `Ø` under `encoding: utf-8`: dropped with `decode`, the next frame read normally. Test in Task 4.

### Task 3: Framer

**Files:**
- Create: `internal/input/serial/frame.go`, `internal/input/serial/frame_test.go`, `internal/input/serial/frame_fuzz_test.go`

**Interfaces:**
- Consumes: `Framing` (Task 2).
- Produces:
  - `type framer struct` built by `func newFramer(f Framing, maxFrame int) *framer`
  - `func (f *framer) push(b []byte, at time.Time) (frames [][]byte, kinds []string)`: bytes read at `at`; returns the completed frames (terminator and `start` removed, CR, LF and NUL trimmed at both ends, empty ones left out) and the kinds counted (`frame_too_long`).
  - `func (f *framer) tick(at time.Time) (frames [][]byte, kinds []string)`: called on every read cycle; ends a `gap` frame after the silence, drops stale bytes with `incomplete_frame` (terminator or length: `2s` after the last byte).
  - `func (f *framer) reset()`: drops what is pending, no kind (port lost).

- [x] **Step 1: Write the failing tests** (table-driven, times built from one base `t0`):
  - terminator `"\r"`: `"1.5\r2.5\r"` gives `1.5`, `2.5`; `"1.5\r\n2.5\r\n"` gives `1.5`, `2.5` and no empty frame; a frame split across three pushes completes once.
  - terminator `"\r\n"` split between two pushes (`"\r"` then `"\n"`) ends the frame once.
  - `length: 4`: `"ABCDEFGH"` gives `ABCD`, `EFGH`.
  - `gap: 50ms`: bytes at `t0`, `t0+20ms`; `tick(t0+60ms)` gives nothing; `tick(t0+71ms)` gives the frame.
  - `start: "\x02"`, terminator `"\x03"`: `"xx\x02AB\x03"` gives `AB`.
  - `max_frame: 8`: a 9-byte run without terminator counts `frame_too_long` once, and the next `"OK\r"` gives `OK` (resync at the terminator); with `length` a too-long setting is refused by Task 2, so only terminator and `gap` are tested here; with `start`, resync at the next `start`.

- `FuzzFramer`: arbitrary bytes split at arbitrary points, every framing mode: no panic, no frame longer than `maxFrame`.

## Delivery status (2026-11-19): shipped

The `serial` input is delivered on branch `feat/serial`: the port on `go.bug.st/serial` with the pseudo-terminal
helper `ptytest`, the connection and its validation, the framer, routing with the sample context, the request
scheduler, the input with its lifecycle, `probe` and `browse`, the documentation and the example in
`examples/serial`. `gofmt -l .`, `go vet ./...`, `go test -race ./...`, `GOARCH=386 go test ./...`,
`GOOS=windows go vet ./...`, `GOOS=linux GOARCH=arm GOARM=7 go build ./...` and
`go test -tags e2e -race ./internal/e2e/...` pass. The end-to-end test `TestSerialInput` runs the real binary on a
pseudo-terminal: a scanned serial followed by two measurements reaches the backend as two samples with
`context.serial`, and a `requests` input writes its command to the port and turns the answer into a sample. The
built-in catalogue of the parent's section 9.2 is complete.

- **Divergences from the spec.**
  - **R1.** `go.bug.st/serial` v1.8.0 no longer brings `creack/goselect` (S12 named it from an older release); on
    Linux and the BSDs it takes exclusive access with `TIOCEXCL`, so a second open fails with "busy".
  - **R2.** `browse` takes an input, like every `browse` of the agent: `browse <input>`, not `browse [<input>]`. A
    technician without a document writes a one-input document with any `device` (shown in USAGE.md).
  - **R3.** `probe` has no `--wait`: it uses the agent's `probeTimeout` (30 s), as `mqtt` does, and returns as soon
    as every point has a sample. A point that stays silent, one whose address duplicates an earlier one included,
    makes it wait the whole 30 s.
  - **R4.** `probe` prints the context it saw and up to ten unmatched frames after the point lines, through the
    optional `probeNoter` interface.
  - **Framer buffer cap.** The framer holds at most `max_frame`, the terminator and 2 bytes: a frame of exactly
    `max_frame` bytes followed by more than two trailing CR, LF or NUL bytes counts `frame_too_long`. Raise
    `max_frame` for such an instrument.
  - **Context history.** The router keeps two entries per key (the current one and the one before it), so the
    context of a sample is the one in force when its frame was read; a frame older than two scans of the same key
    finds no value for it.
  - **Task 6 test durations.** Two lifecycle tests take 1.5 s and 7.5 s of real time, from the real backoff, which
    the fake clock does not drive.
  - **Choices the spec left open** (rulings during the build): the maximum `max_frame` is 65536; boundaries are
    inclusive for `gap` and the 2 s stale rule; frames are trimmed of CR, LF and NUL in every mode; a second start
    character restarts the frame; requests are sent earliest-due first, ties in document order, the next due time
    counting from the send; the scheduler lives per open port; `CheckBuild` stopped refusing `serial` in Task 2,
    before the factory of Task 6.
  - **Final review wave (2026-11-19).** The whole-branch review found twelve items, fixed before the merge:
    - a numeric point drops the leading zeros of its value text (Mitutoyo Digimatic `01A+00012.345` reads
      `12.345`), in the router, without changing `driverkit.ConvertText`;
    - `OpenPort` flushes the input buffer (`ResetInputBuffer`), and the framer starts syncing on construction and
      after a reset: bytes are dropped until a quiet read cycle, a start character or a terminator (with `gap`, the
      first silence of `gap`), counting `incomplete_frame` once, so a gauge streaming across the open never gives
      a half frame; `probe` inherits it. Tests that fed bytes in the very first read now first see a quiet cycle or
      a terminator;
    - `lograte` gained the option `SummaryAtReportedLevel` (existing callers unchanged): the unmatched summary stays
      at `debug`, and the input flushes it on `Close`;
    - the backoff and the once-per-cause open warnings reset only once the port holds (a frame read, or open for
      `BackoffMax`); `port_lost` is counted on every loss and warned once per episode, which a frame ends;
    - the context change is logged only when the value in force changes (an expired key counts as absent), and the
      "context dropped" line at `Close` only when a key is still in force;
    - two `serial` inputs with the same `connection.device` are refused at validation
      (`inputs.<i>.connection.device: the same port as inputs.<j>`), since root ignores `TIOCEXCL`; the docs say
      exclusive use is not enforced for root on Linux;
    - a gap frame is stamped with the time of its last byte (the framer returns each frame with its read time);
    - `probe` escapes context values and `browse` escapes the USB vid and pid;
    - the docs state that `start`, `terminator` and `command` are UTF-8 strings (use ASCII) and how an RS-485
      adapter echo frees the request slot.
- **Known limits.** No keyboard-wedge (HID) readers and no regular-expression framing (spec section 2 and S4); no
  binary frames; a context only in memory; no real instrument or COM port in the tests. Recorded in the spec and in
  the docs.
